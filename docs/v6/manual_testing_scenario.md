# Google Meet Chat to Clipboard v6 実機手動テストシナリオ・チェックリスト

本ドキュメントは、**Google Meet v6 DOM 対応**（自動保存オフ検出・SPA Room 遷移・PinP 境界・メッセージブロック単位抽出）の実機環境（Chrome 拡張機能 + 実際の Google Meet 画面）における手動検証シナリオです。

---

## 1. 事前準備（テスト環境のセットアップ）

1. **拡張機能のロード**:
   - Chrome で `chrome://extensions/` を開く。
   - 「デベロッパーモード」をオンにする。
   - 「パッケージ化されていない拡張機能を読み込む」から本プロジェクトのディレクトリ（`GoogleMeetChatToClipboard`）を選択して読み込む。
   - 拡張機能バージョンが `5.2.0` であることを確認。

2. **テスト対象ミーティングの用意**:
   - **ケース A**: Google Workspace アカウント等の「チャット保存オン」ミーティング（保存対象外）
   - **ケース B**: 個人の Google アカウント等の「チャット保存オフ（`div.hsLqkc` 存在）」ミーティング（保存対象）

3. **確認用ツール・前提**:
   - 拡張機能を再読み込みした後、Meet のタブも再読み込みしてからテストを開始する。
   - DevTools の Console にエラー（`TypeError`、`ReferenceError`、clipboard エラー）が出ていないことを確認する。
   - コピー結果は、貼り付け先の既存テキストと混同しないよう、空のテキストエディタへ貼り付けて確認する。
   - Chrome の仕様上、`beforeunload` ダイアログは自動操作・一部のリロード方法では表示が抑制される場合がある。その場合は Console エラーがなく、ログが一時保存されることも確認する。

### 判定基準

- Console に未処理の例外がない。
- 対象ミーティングではコピー、退出後 UI、PinP が動作する。
- 対象外ミーティングでは UI 注入、クリップボード書き込み、離脱確認が発生しない。
- SPA 遷移後に旧 Room のログ・名前・処理済み属性が新 Room へ混入しない。
- `npm test` および `npm run build` の成功だけでは実機合格とせず、本シナリオの完了欄を根拠にサインオフする。
