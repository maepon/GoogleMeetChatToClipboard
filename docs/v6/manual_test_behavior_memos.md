## 挙動メモ一覧

### 挙動メモ①: 退出後画面からの遷移（ホームに戻る・再参加）時に beforeunload ダイアログが表示される

- **発生事象:**  
  通話中に退出ボタンを押して正常に退出した後、退出後画面（「通話から退出しました」画面等）において「ホーム画面に戻る」ボタンや「再参加」ボタンを押して画面遷移しようとすると、`beforeunload` の確認ダイアログが表示されてしまう。
- **背景・原因の考察（暫定）:**  
  退出操作完了後も `AppState.wasSaveTarget === true` および `AppState.pendingExitChatLogText` が保持されており、Room ID も同じ状態のまま退出後画面から離脱（URL 変更）しようとするため、`beforeunload` ハンドラーの条件を満たしてダイアログを要求してしまう。
- **論点・今後の検討事項:**  
  - 「Meet 通話中（ミーティング中）のリロード・タブ閉じ」と、「退出完了後の画面からの離脱」を切り分ける条件が必要。
  - 例：自動コピーが完了している場合（`autoCopySucceeded === true`）、または退出後画面が既に表示されている場合（`exitedUIInserted` や退出後 DOM 存在時）に `beforeunload` でのダイアログ要求を抑止する、などの切り分け方針。
- **ステータス:** メモ記録完了（実装は行わず保留中）

### 結果メモ②: リロード・タブ閉じ時のダイアログ要求成功と、キャンセル後画面からの遷移時ダイアログ

- **確認できた期待動作 (OK):**  
  - 会議中の**リロードボタン押下（Cmd+R / F5）およびタブ閉じ（Cmd+W）時に、期待通り Chrome の確認ダイアログが表示される**ことを実機確認。
  - ダイアログで「キャンセル」を選択後、同一画面に留まり、textarea にチャット内容が正常に保持されることを確認（TC-1.5 の基本検証成功）。
- **発生した事象（課題）:**  
  - キャンセル後、その画面から別の画面へ遷移しようとすると、再びダイアログが表示される。
- **背景・原因の考察（暫定）:**  
  - メモ①と同様の機序。キャンセル後も `wasSaveTarget = true` および `pendingExitChatLogText` が保持されたまま残るため、後続の別画面への意図した遷移時にも `beforeunload` が発火してダイアログを要求してしまう。
- **ステータス:** メモ記録完了（実装は行わず保留中）
