# v6 スコープおよびエッジケース対応方針

**文書ステータス:** Approved
**対象:** v6 の実装、テスト、コードレビュー、完了報告
**適用開始:** 承認日以降

## 1. 目的

本書は、v6 において「どこまでを今回の対応で保証するか」と「どのエッジケースを追加課題として扱うか」を共有するための方針である。

個別の不具合報告書は原因、変更内容、テスト結果を記録する文書とし、保証範囲や対象外事項は本書を基準とする。これにより、個別報告書ごとに「100%」「すべての潜在的不具合」などの保証範囲が拡大解釈されることを防ぐ。

## 2. 共通の完了条件

v6 の今回対応は、次の条件を満たした場合に完了と判定する。

> 本対応は、同一 JavaScript コンテキスト内で退出後 DOM が表示されるケースを対象とし、定義済みの P0 条件において、自動コピー成功時の不要 UI 非表示、コピー失敗時のフォールバック UI 表示、Room 間のログ混入防止を保証する。ページ離脱確定後の復元や、未知のブラウザ・Google Meet 仕様変更は対象外とする。

完了判定では、次のすべてを確認する。

- P0 に分類された受入条件をテストまたは実機確認で検証する。
- 既存の関連テストと追加テストが成功する。
- テストコマンドがタイムアウトせず、終了コード `0` で終了する。
- 失敗したテストがある場合、原因を修正するか、P1/P2として合意済みの未対応事項に記録する。
- 完了報告書には、検証した条件、未検証の条件、対象外の条件を分けて記載する。

## 3. 優先度の定義

### P0: 今回の受入条件

P0 は、今回の不具合修正および v6 の基本動作として必ず保証する範囲である。

#### 3.1 ライフサイクルと検出

- `beforeunload` ダイアログ表示後にキャンセルし、同一ページ・同一 JavaScript コンテキストへ戻る。
- 退出後 DOM が `MutationObserver` の登録前に存在する場合でも検出できる。
- 退出後 DOM に追加の変更がなく、`MutationObserver` のコールバックが発火しない場合でも検出できる。
- 退出後 DOM から保存対象インジケーター `div.hsLqkc` が消えていても、会議中に保存対象だった状態を利用して判定できる。
- 退出後要素が検出された時点で退避ログが未確定なら、`data-gmctc-processed` を付与せず、後続のチェックに委ねる。
- 初回直接チェック、`MutationObserver`、定期チェックのいずれから検出されても、退出後 UI を二重生成しない。

#### 3.2 コピーとフォールバック UI

- 自動コピーが正常完了した場合、退出後の不要な textarea を表示しない。
- Clipboard API と `execCommand` を含む自動コピー経路が最終的に失敗した場合、手動コピー用のフォールバック textarea を表示する。
- `navigator.clipboard` が存在しない、または `writeText` が利用できない場合、例外で処理を停止せずフォールバック経路へ進む。
- コピー処理が完了する前に退出後 DOM が検出された場合、コピー結果が確定するまで UI 判定を保留する。
- 自動コピー成功状態と退出後 UI からの手動コピー成功状態を混同しない。

#### 3.3 Room 間の状態分離と退出時ライフサイクル

- Room A のログを退出後画面で利用できる。
- `Room A → /landing → Room B` の遷移で、Room A の退避ログ、対象フラグ、退出後 UI 状態を Room B に持ち込まない。
- `Room A → /landing → Room A` の再参加時に、新規セッションとして旧セッションの退出状態（`postExitCompleted` 等）と退避ログをリセットし、新セッション会議中の離脱確認を維持する。
- 退出後画面（`postExitCompleted === true`、フォールバック UI 挿入後等）からのホーム・再参加遷移では `beforeunload` ダイアログを抑止する。
- 会議中の手動コピー成功後でも、退出前であれば会議中リロード・タブ閉じ時の `beforeunload` ダイアログ要求を維持する。
- Room 遷移時に旧コンテナの退出要素を処理済みとして扱い、旧 Room の UI を新 Room で再利用しない。

### P1: 追加の堅牢化

P1 は重要な改善候補だが、P0 の受入条件および TC-1.5 の再現条件とは分けて管理する。P1 未対応の場合、完了報告書に未対応事項として明記する。

- コピー処理ごとの世代番号またはトークンを導入し、古い Promise の完了処理が新しいコピー状態を書き換えないようにする。
- SPA の Room 遷移後に、旧 Room の Promise や PinP の `setTimeout` 完了処理を無効化する。
- `navigator.clipboard.writeText()` 自体が同期例外を投げる場合にも、`copyInProgress` が残留しないようにする。
- PinP のコピー待機中に Room 遷移、PinP 閉鎖、対象 document の破棄が起きた場合を扱う。

### P2: 今回は保証しない範囲

P2 は、今回の対応では保証しない。必要になった場合は、別のIssueまたは別の受入条件として扱う。

- ページ離脱を確定した後の完全リロード。
- 新しい JavaScript コンテキストでのログ復元。
- ブラウザ終了、クラッシュ、強制終了、タブのバックグラウンド破棄。
- 複数タブ間の AppState や退避ログの同期。
- Google Meet 側の DOM セレクター変更や、未知の画面遷移。
- ブラウザ固有の Clipboard 権限 UI、権限ダイアログ、実装差異のすべて。
- ネットワーク障害や Google Meet サービス側の障害によるチャット DOM 欠落。
- Room トークンや退出世代管理を伴わない、未処理 stale DOM（`data-gmctc-processed` 未付与の旧要素）の完全識別。

## 4. 判定マトリクス

| ケース | 分類 | 必須結果 |
|---|---|---|
| 退出後 DOM が Observer 登録前に存在 | P0 | 退出後 UI または成功時の処理済み化が行われる |
| 退出後 DOM に `div.hsLqkc` がない | P0 | 会議中の保存対象状態と退避ログで判定する |
| 自動コピー成功 | P0 | textarea を生成しない |
| 自動コピー経路が最終的に失敗 | P0 | textarea を生成する |
| Clipboard API 未提供 | P0 | 例外停止せずフォールバックへ進む |
| コピー Promise 保留中 | P0 | 結果確定まで UI を生成しない |
| Room A から `/landing` | P0 | Room A の退避状態を退出後画面まで保持する |
| `/landing` から Room B | P0 | Room A の退避状態を消去する |
| `/landing` から Room A 再参加 | P0 | 旧セッションの退出状態をリセットし新規会議中要求を維持 |
| 退出後画面からの遷移（ホーム・再参加） | P0 | `beforeunload` ダイアログを抑止する |
| 会議中コピー後の離脱 | P0 | `beforeunload` ダイアログ要求を維持する |
| コピー A とコピー B の完了順序が逆転 | P1 | 最新世代だけが状態を更新する |
| コピー API 呼び出し自体が同期例外 | P1 | 処理中フラグを残さずフォールバックする |
| 完全リロード後のログ復元 | P2 | 今回は保証しない |
| ブラウザクラッシュ後のログ復元 | P2 | 今回は保証しない |

## 5. テストおよびレビューの基準

### 5.1 テストの記載方法

個別報告書では、テストを次のように分類して記載する。

- **P0受入テスト:** 完了条件に直接紐づくテスト。成功が必須。
- **関連テスト:** P0を補助する既存機能または実装経路のテスト。
- **P1検討テスト:** 追加堅牢化の再現テスト。未実装の場合は未対応と記録する。
- **P2対象外:** テストを実施せず、対象外理由を記載する。

テスト結果は assertion の成功数だけでなく、コマンドの終了コード、タイムアウトの有無、実行環境を記録する。たとえば `PASS: 28, FAIL: 0` でもプロセスがタイムアウトした場合は、「全 assertion 成功、プロセス終了は未確認」と表現し、完了条件を満たしたとは断定しない。

### 5.2 レビューで避ける表現

検証範囲を超える保証を避けるため、次の表現は単独で使用しない。

- `実機 100% 検出保証`
- `すべての潜在的不具合を解消`
- `絶対に表示しない`
- `どの環境でも確実に動作する`

代わりに、次のように条件を明記する。

- `定義したP0条件下で検出を確認`
- `今回定義したP0の不具合を解消`
- `自動コピーが正常完了するP0条件ではtextareaを生成しない`
- `確認したブラウザ・DOM・JavaScriptコンテキストの範囲で動作を確認`

## 6. 個別文書との関係

本書は v6 共通の判定基準であり、個別文書は本書を参照して対象範囲を記載する。

- [TC-1.5 調査報告および確定修正仕様書](./tc1_5_investigation_report.md): 退出後 textarea 不表示の原因と修正仕様。
- [コピー制御・非同期競合防止 改修完了報告書](./review_fix_completion_report.md): コピー状態管理と関連テストの実装記録。
- [v6 DOM Selector Workspace](./README.md): v6 の selector と実装方針の案内。

個別文書で本書と異なる保証範囲を設定する場合は、本文書の変更ではなく、対象テストの受入条件として明示し、レビュー時に合意を取る。

## 7. すり合わせ事項

今後の運用上、次の点は必要に応じて合意・更新する。

1. P0 の「コピー Promise 保留中は UI を生成しない」を TC-1.5 の必須条件として扱うか。
2. P1 の世代管理、同期例外、PinP 待機中の遷移を、次回リリースの受入条件へ昇格するか。
3. `setInterval()` の自然終了確認を、v6 全体の完了条件に含めるか。
4. Clipboard API 未提供時に `execCommand` が失敗した場合の表示文言・手動操作を追加定義するか。
5. 実機確認で対象とするブラウザ、Google Meet の画面状態、PinP の有無を固定するか。

本書の承認により、各個別報告書の保証表現は本書に合わせる。
