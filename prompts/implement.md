# impl-4 — 承認済みの計画どおりに実装する（高速モデル）

Issue #{{ISSUE}} の**承認済みの実装計画書どおりに実装**するのがあなたの仕事です。

## 手順

1. `gh issue view {{ISSUE}} --comments` を読む
   - `<!-- AI-TAG: INSTRUCTION -->` が仕様の正
   - **最新の** `<!-- AI-TAG: PLAN -->`（`verdict=APPROVED` を得たもの）が実装の手順書
2. 受入基準が Google Meet の DOM 挙動に関わるものなら、`test/v6_dom_test.js` に
   テストシナリオのテストケースを先に追記し、**落ちることを確認**してから実装する
   （既存の `createEnvironment` 等のヘルパーとテストケースの書き方に合わせる）
   - DOM に依存しない受入基準（ロケールファイルの構造・`manifest.json` の値など）は、
     `tmp/` の下に確認用スクリプトを `Write` で作り、`node tmp/<ファイル名>.js` で
     実装前に期待どおりでないことを確認する
   - すでに満たされている受入基準については、あらためて確認し直す必要はない
   - 受入基準が「実装を一時的に改変して挙動が変わることを確認する」ことを明示的に
     求めている場合はそれに従う。ただし**確認したら必ず元に戻し**、戻したことを
     `git diff` で確かめてから報告する
3. `npm test` が全て通ることを確認する。落ちたまま報告しない。DOM に依存しない
   確認は同じ `node tmp/<ファイル名>.js` の呼び出しで期待結果と一致することを確認する
4. 該当するドキュメント（`CLAUDE.md` / `README.md`）を更新する
5. **コミットしない。** 変更は作業ツリーに残す。次のフェーズが差分を読む
6. 完了報告を投稿する

## 計画から外れたくなったら

実装中に計画の不備に気づくことはあります。そのときは**勝手に直さず**、
計画どおりに実装できる範囲まで進めて、外れた点と理由を報告に書いてください。
次のレビューフェーズがそれを見て判断します。

## 完了報告に含めるもの

先頭タグ: `<!-- AI-TAG: IMPLEMENTATION_DONE -->`

- **変更したファイル**と、それぞれ何をなぜ変えたか
- **受入基準ごとの対応表** — `AC-n` / 対応したコード / 検証したテストケースまたは `tmp/` スクリプト / 結果
- `npm test` の実行結果。DOMに依存しない確認があれば `node tmp/<ファイル名>.js` の結果も
- **計画から外れた点**（あれば）と理由。無ければ「なし」と書く

## 最後に

実装内容の要点を3行程度でまとめて返答してください。
